## 0. 가장 중요한 정정 — 연구 "E" ≠ production

연구 문서에서 **E** 로 부른 전략은 `BRK15`(돌파대기) + `RS125`(RS 상위 증액) +
`EARLY-PASS` 를 얹은 것인데, **이 셋은 production 코드에 존재하지 않는다.**
하네스 monkeypatch 로만 구현된 연구 전용 전략이다.

```
app/trading/macd2/ 에서 BRK15 / RS_UP / EARLY_PASS 검색 -> 0건
harness: RSBRK = (VAR == "UPFASTRS")      <- 연구 코드에만 있음
```

실제 운영은 `strategy_mode = P3` 이고 연구 문서의 **A** 다.

| | 85일 총손익 | production |
|---|---|---|
| **A = P3** (실제 운영) | +17,227,606 | ✅ |
| E = A + BRK15 + RS125 + EARLY-PASS | +18,435,036 | ❌ 연구 전용 |

**따라서 연구 CHOP-STACK 수치를 production CHOP 의 성능으로 간주하면 안 된다.**
아래는 전부 **P3 기준**으로 다시 측정한 값이다.

## 4. SLOW-TP2 — 9~10월 검증 불가

9~10월 23영업일에서 **발동 0건**이라 Δ = 0 이다. 연구에서도 SLOW-TP2 의 발동일 7일이
전부 5~8월이었다. **이 부품의 검증은 85영업일 재생에서만 가능하다.**

후보 탐지(net 3.85~4.25% & 보유 ≥ 25분)로 9/22 를 뽑아 재생했으나 실제로는 발동하지
않았다 — 실제 조건(N1 **비추세 가지** + `tp1_done`)이 성립하지 않았기 때문이다.
즉 **후보 탐지 휴리스틱이 실제 발동조건의 상위집합**이다. 85일 재생 시 이 점을 감안해
후보일을 넉넉히 잡아야 한다.

## 6. 구현 중 발견한 버그 4건 (전부 수정됨)

1. **CHOP 모드가 재시작을 못 넘김** — `strategy_mode.restore()` 가 저장 모드를
   `infer_from_legacy` 와 대조하는데 그 함수가 CHOP 을 몰라 **모드 기록이 지워지고 P3 로
   되돌아갔다.** → `infer_from_legacy` 에 CHOP 인식 추가.
2. **새 운영 플래그 미직렬화** — `chop_defense_enabled` 가 저장되지 않아 1번을 악화시켰다.
   → `state_store` 에 CHOP 필드 추가.
3. **`note_bars` 훅 위치 오류** — `initialize_strategy_session`(세션 1회)에 넣어서 실제 틱
   경로에서는 박스 캐시가 비어 **구조손절이 한 번도 발동하지 못했다.** → 틱 경로로 이동.
4. **검증 하네스의 모드 지정 무효** — `VAR` 정규화가 `strategy_mode.apply()` 보다 앞서
   CHOP 이 P3 로 돌고 있었다. → `WK_PRODMODE` env 로 분리.

1·2 는 기존 테스트(`test_mode_survives_a_state_roundtrip`)가, 3·4 는 재생 결과가 P3 와
완전히 동일하게 나온 것이 잡아 주었다.
