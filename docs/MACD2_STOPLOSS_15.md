# 오전 손절 −1.3% → −1.5% (2026-11-02)

## 바뀐 것

`config.X2LITE_MORNING_STOP_LOSS` **−0.013 → −0.015** 하나다.
이 값은 **N1 계열 + X2-lite 계열**이 공유하므로, 현행 운영모드(CHOP = N1 래더)의
**오전 손절**이 −1.5%가 된다. env `MACD2_X2LITE_MORNING_STOP_LOSS` 로 즉시 되돌릴 수 있다.

## 바뀌지 않은 것 — "모든 손절"이 −1.3% 였던 게 아니다

| 손절 | 상수 | 값 | 적용 |
|---|---|---|---|
| **오전(변경됨)** | `X2LITE_MORNING_STOP_LOSS` | **−1.5%** (구 −1.3%) | N1 계열 · X2-lite 계열 |
| 오후 | `AFTERNOON_STOP_LOSS` | −1.2% | 오후 진입 전부 (**override 없음**) |
| TW2 / TEGv2 / MU_MACD | `MORNING_STOP_LOSS` | −1.7% | 그 모드들 |
| TW TEG 3-SLOT (F) | `TWF_MORNING_STOP_LOSS` | −1.4% | F |
| B3 구조손절 | `P3_B3_SL_PCT` | −1.0% | **CHOP 각인 진입** (B3 관리) |

오후 래더와 B3 는 이번 변경과 무관하다. CHOP 모드로 운용 중이라도 **진입 regime 이
CHOP 으로 각인되면 B3(−1.0%)가 먼저 관리**하고, TREND 각인일 때 이 −1.5% 가 쓰인다.

## 판정 방식 (이 변경을 이해하는 핵심)

손절은 **틱이나 저가가 아니라 보유 ETF 의 완성 3분봉 종가**로만 판정하고,
**진입봉은 제외**한다 — `worker._advance_stop_loss_bar` → `bar_net_return` →
`time_window_position_manager.evaluate_position`. 그래서 "장중에 −1.4% 를 찍었다"가
아니라 "3분봉이 −1.5% 아래에서 닫혔다" 일 때만 나간다.

## 실측 — 58영업일에서 **손익 변화 0**

기간 2026-08-03~10-30 (ETF 1분봉 실데이터 구간), 구성 = CHOP + MU Assist + XS
(= 연구 tag `L85_A`, 현행 운영구성).

| | A (−1.3%) | B (−1.5%) | Δ |
|---|---|---|---|
| 거래수 | 99 | 99 | **0** |
| 총손익 | +6,676,673 | +6,676,673 | **0** |
| PF | 2.255 | 2.255 | **0** |
| MDD | 636,248 | 636,248 | **0** |
| 최악일 (10/12) | −351,414 | −351,414 | **0** |
| 승률 | 53.5% | 53.5% | **0** |
| 손실일수 | 21 | 21 | **0** |

TW 손절 20건 전부 **같은 봉·같은 가격**에서 걸린다. 3분봉 종가가 −1.3~−1.5 의
0.2%p 띠에 멈춘 사례가 그 기간에 **한 건도 없기** 때문이다.

### 측정 신뢰성

- **회귀**: env 로 −0.013(현행값)을 주고 돌린 08/03 이 기준선과 주문·진입 **완전 동일**
- **극단 probe**: 같은 경로로 **−5%** 를 08/20 에 적용 → 손절이 09:15 @8,125 →
  **09:21 @7,935** 로 이동. 즉 이 env 가 실제로 판정을 바꾼다(Δ 0 이 '노브 고장'이 아니다)

### 더 넓히면

| 손절 | 결과 |
|---|---|
| −1.5% | **Δ 0** (58일 전량) |
| −1.8% | 혼합 — 측정한 5일에서 2건 생존(+250,871 / +144,780) · 3건 악화. **18일 전수는 미완** |
| −2.0% | **−1,116,485** (10/16~10/30 N1 손절 16건, `research_20261102_shake_tolerance`) |

−1.8% 는 아직 결론이 아니다. 측정한 5일은 "얕은 손절"만 고른 편향 표본이다.

## 재현

```bash
export WT=<wt_arm3 (운영 HEAD)> REPLAY_SP=<b3t_sp> ARM3_RT=<arm3_sp/rt> ARM3_OUT=<out>
R=research_20261030_tick_arm3/scripts/r1_run.py
B="--harness ARM3 --var ARM3 --env WK_MODE=CHOP --env WK_ARM=NONE --env WK_TICKPX=0 \
   --env MACD2_T2_SHADOW_ENABLED=0 --env MACD2_P70R_SHADOW_ENABLED=0"

# 회귀 — 현행값을 env 로 주면 기준선과 동일해야 한다
python $R $B --tag CHK_SL13 --env MACD2_X2LITE_MORNING_STOP_LOSS=-0.013 --env WK_MUA=0 --env WK_XS=0 20260803

# 본 검정 — TW 손절이 있던 18일만 (나머지 40일은 손절 미발동이라 코드상 동일)
python $R $B --tag SL15 --env MACD2_X2LITE_MORNING_STOP_LOSS=-0.015 --env WK_MUA=0 --env WK_XS=0 -j 3 \
    20260803 20260805 20260810 20260811 20260812 20260820 20260821 20260824 20260827 \
    20260831 20260903 20260915 20260930 20261012 20261013 20261014
python $R $B --tag SL15 --env MACD2_X2LITE_MORNING_STOP_LOSS=-0.015 --env WK_MUA=1 --env WK_XS=1 -j 2 \
    20261021 20261026
```

손절일 선별은 기준선 산출의 `TIME_WINDOW_STOP_LOSS` act 로 한다. 집계는
A 산출을 생략일에 채워 비교한다(코드상 동일 보장).

### 함정

1. **오프라인으로 3분봉 종가를 재구성해 임계값을 스윕하면 경계 거래에서 틀린다.**
   재생의 봉 종가는 "그 봉 마지막 20초 tick 의 **분내 선형보간 가격**"이지 1분봉 종가가
   아니다. 실제로 −1.5% 구간에서 모델은 9건 변화를 예측했지만 재생은 0건이었다
   (모델 net% 가 약 0.05%p 낙관적). **경계 판정은 반드시 재생으로 한다.**
2. 손절선을 바꾸면 **그 거래만 바뀌는 게 아니다** — 살아남은 포지션이 슬롯과 이후
   진입을 바꾼다(09/15 는 손절이 사라지면서 `B3_MAXHOLD` 로 +101,645 가 됐다).
