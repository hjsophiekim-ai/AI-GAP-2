## 1. 체결모델 — 무엇을 바꿨나

| | 이전(낙관적) | **이번(faithful-fill)** |
|---|---|---|
| 체결가 | 확정봉 **자기 종가** `etf_close[bar_ts]` | **`nearest_close(etf_1m, 봉시작+3분)`** = T+3 인식시점 실호가 |
| 불완전 3분봉 | 그대로 사용 | **production `filter_complete_3m_bars` 로 제거** |
| 보유 래더 | 항상 평가 | 보유 ETF 의 그 봉이 **완성봉일 때만** 평가 |
| `entry_idx` | `idx` | **`idx + 1`** (체결이 일어나는 버킷 제외) |

근거: `scripts/tw_gate_corrected_clock_engine.py` (2026-08-20) 와 memory
`project_macd2_backtest_clock_semantics_fix`. 3분봉은 벽시계가 T+3 을 지나야
완성으로 인식되고 production 은 **그 시점의 실제 호가**로 체결한다. 확정봉 자기
종가로 체결하는 것은 그 엔진이 "FILL-PRICE LOOK-AHEAD" 로 지목한 바로 그 버그다.

### 동치/정합 확인

- `Quotes.at()` 가 검증엔진의 `tw_gate_corrected_clock_engine.nearest_close` 와
  **표본 800건(LONG 400 / INVERSE 400) 전부 일치** — 불일치 0건.
- 불완전봉 제거: hynix **158 / 9457봉**, LONG 216, INVERSE 228.
  → hynix 완성봉 9299봉, 확정 플래그 694 → **672건**.

### ⚠ 검증의 한계 (반드시 같이 읽을 것)

1. `tests/macd2/test_backtest_worker_clock_parity.py` 는 현재 **xfail** 이다.
   진입 시각·건수·체결가는 real worker replay 와 일치하지만 **청산 시각에 ~5분
   괴리**가 남아 있다(테스트 자신의 xfail 사유, 미해결). 이 체결모델은 "이 저장소에서
   가장 잘 검증된 모델"이지 "완전히 증명된 모델"이 아니다.
2. **실계좌 체결과의 대조는 이 머신에서 불가능하다.** `data/logs/macd2_execution_ledger.csv`
   는 21행 전부 `mode=mock` 이고 타임스탬프도 15:36/23:21 같은 개발 아티팩트다.
   실거래 원장은 Render 에 있다([[project_macd2_live_deployment_location]]).
   따라서 "A가 현실을 재현한다"는 것은 **검증된 primitive 를 쓴다는 뜻**이지
   실체결과 대조했다는 뜻이 아니다.
3. 슬리피지·부분체결·호가공백은 여전히 미반영. 수수료/세금은 production
   `TradeCostEngine`(`worker._net_return_pct`) 으로 반영됨.
