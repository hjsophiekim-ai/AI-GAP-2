## 6. 메커니즘 — 왜 C 가 B 에 지는가 (구조적 이유)

| 대조 (70일) | 사라짐 | 신규 | 유지 | 청산사유 변경 | 변경분 기여 |
|---|--:|--:|--:|--:|--:|
| A → B | 6 | 3 | 138 | 22 | **+5.311%p** |
| A → C | 5 | 2 | 139 | 21 | **+0.659%p** |

**진입집합은 사실상 그대로이고 청산만 바뀐다**(H50 계열의 원래 성질 그대로).
문제는 C 의 청산 변경이 벌어들이는 양이 B 의 1/8 이라는 점이다.

**B → C 에서 청산사유가 바뀐 20건: 개선 10 / 악화 10, 합 음수** (전량
`c_vs_b_changed_exits.csv`).

| 개선 예 | | 악화 예 | |
|---|--:|---|--:|
| 20260615 STOP_LOSS 14:36 → watch 13:51 | **+2.019** | 20260618 H50_EXIT 12:33 → watch 11:36 | **−3.290** |
| 20260903 STOP_LOSS 10:33 → watch 09:51 | +1.987 | 20260616 H50_EXIT 12:45 → watch 11:48 | −2.509 |

| 20260909 STOP_LOSS 12:12 → watch 12:00 | +1.279 | 20260813 EARLY_TP 13:15 → watch 12:42 | −1.215 |

패턴이 선명하다: **손절로 갈 거래는 더 싸게 끊어주고(개선), 끝까지 갔으면
이겼을 HOLD 는 중간에 잘라버린다(악화).**

### 근본 원인 — 두 로직의 전제가 다르다

`evaluate_whipsaw_watch` 는 **"gap 이 확대되지 않아서"** 보류한 TW 분기
(`TW_WHIPSAW_REJECT_REASONS` = `REJECT_NOT_CONFIRMED` /
`REJECT_MACD_GAP_NOT_EXPANDING`)의 후속 확인기다. 즉 **평평한 gap 에서 출발**해
다시 확대되는지를 본다.

H50 은 gap 과 **무관하게** 보류한다(상위추세 정렬 + 좁은 rng60). 그래서 이미
강하게 확대 중인 gap 위에서 같은 "직전 대비 재확대" 규칙을 걸면 대부분 **다음
한 봉에서 바로** 발화한다:

| | 70일 WATCH 청산 | 70일 H50 자체 청산 |
|---|--:|--:|
| B | 1건 | 8건 |
| C | **23건** | 2건 |

H50 의 고유 해제경로(추세 2봉 이탈 / 60분)가 8건 → 2건으로 거의 사라진다.
**연결이 H50 을 보조하는 게 아니라 대체해 버린다.**

### arm 시점 — 1회 vs 매 반대플래그

production 의 TW 분기는 반대 플래그마다 re-seed 한다. 그대로 따라 하면
70일 +189.59% 로 **한 번만 arm(+193.51%) 보다 더 나쁘다.** 그래서 구현은
**HOLD 가 처음 시작될 때 한 번만 arm** 하는 쪽으로 고정했다.
