## 1. C 규칙 (지시대로)

```
진입/폐기/trigger 로직은 기존 EARLY-PASS 그대로 (한 줄도 바꾸지 않음)
즉시진입 거래는 기존 TP 그대로
돌파대기 후 체결된 거래만:
  TP1 / TP2 / 오후TP / B3_TP / P3_PARTIAL / P3_H30_PARTIAL 의 기준 수익률을
  실제 체결가가 아니라 T+3 승인시점 참조가(= 그 시각 ask1 = 시세 + 1틱) 기준으로 계산
손절 계열은 전부 실제 체결가 기준 유지:
  STOP_LOSS / AFTER_TP1_STOP / TRAILING_STOP / BREAKEVEN_STOP / B3_SL /
  max-hold / C1 peak protection / 조기익절(ETP) / H50 / 반대신호
```

구현은 `worker._net_return_pct` 를 감싸 **같은 현재가에 대한 참조 수익률**을 따로
계산해 두고, 익절 판정 함수(`evaluate_take_profit_immediate` / `evaluate_position` /
`p3_stack.evaluate`)에서 익절 결정만 그 값으로 바꿉니다. 손절 결정은 실제 수익률로
내린 결과를 그대로 씁니다. peak 추적기(트레일링·after-TP1-stop 입력)도 실제 기준
값을 유지합니다.

## 8. 판정 근거

**INSUFFICIENT SAMPLE.**

채택을 막는 것은 성능이 아니라 **근거의 양**입니다.

1. **표본 5건**이고 **2건이 악화**됐습니다(−19,949 / −34,839). 순효과 +114,366 은
   3건(+56,483 / +63,048 / +49,623)에서 나옵니다. 한 건만 빼도 결론이 흔들립니다.
2. **in-sample 전용입니다.** 이 규칙은 "9월 약점의 원인 = 돌파대기 5건의 진입가 상승"
   이라는 진단에서 나왔는데, 검정도 **그 5건에서만** 했습니다. 85일 전체 돌파대기 체결
   **37건 중 5건(14%)** 만 본 것이라 out-of-sample 근거가 없습니다.
3. **A 를 회복하지 못합니다.** C 는 여전히 9월에 A 보다 −427,519 뒤집니다. 9월 손상
   −541,885 중 **21%** 만 회수합니다. "EARLY-PASS 를 쓰되 9월 손해를 없앤다"는
   목표에는 한참 못 미칩니다.
4. 다만 **B 보다는 명확히 낫습니다** — 총손익 +114,366, PF 1.61→1.73, 손실일 6→5,
   승률 50.0→52.8%, 그러면서 MDD(−4.97%)·최대1일손실(−324,408)·폐기집합은 불변이고
   일일한도 초과 0일입니다. **새로 생긴 위험은 없습니다.**

### 결론을 가르는 다음 한 가지

85영업일 전체(돌파대기 체결 37건 / 32일)로 같은 검정을 돌리는 것입니다.
그때 **개선 상위 1·2건을 빼고도 우위가 남고**, 악화 건수가 지금 비율(2/5)보다
늘지 않으면 USE REFERENCE-TP 로 바꿀 근거가 됩니다. 지금 수치로는 바꿀 수 없습니다.

## 9. 한계

- 표본 5건, 전부 UP 방향. DOWN 돌파대기 체결은 이 구간에 없어 **검증되지 않았습니다**.
- 참조가 = 승인 시각의 ask1(시세 + 1틱)로 정의했습니다. A 가 실제로 그 가격에 샀는지는
  A 의 체결기록과 대조하지 않았습니다(09/10 은 11,975 로 일치 확인).
- 조기익절(ETP)은 익절 계열이지만 **실제 체결가 기준으로 두었습니다** —
  "청산 다른 로직은 건드리지 말 것" 지시에 따라 지정된 TP1/TP2/B3_TP 계열만 바꿨습니다.
- 돌파 판정은 1분봉 시가→종가 선형보간 호가 경로 기준이라 분봉 내부 wick 돌파를 놓칩니다.
- 기존 공통 전제(live/backtest 플래그 재현율 미해결) 그대로. 절대수익률은 PROVISIONAL.
