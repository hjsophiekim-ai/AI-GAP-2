# MU 플래그를 원신호로 쓰는 단순 전략 (2026-11-04, research only)

production 무수정 · 읽기 전용. 재생은 격리 워크트리(`wt_arm3` = 운영 HEAD `368e4bf`) + 하네스 **사본**.

핵심 질문 — **"복잡한 HY 플래그 구조보다, MU 플래그 → CONFIRM/WAIT/BAD 라는 단순 구조가
수익과 안전성을 더 좋게 만드는가?"**

7건으로 줄이면서 MDD 를 311,536 → 81,388 로 낮춘다. HY 구조는 군더더기가 아니었다.

## 1. 원신호 정의 (production 계산식 그대로)

MU 1분봉 종가 → MACD(12,26,9, `adjust=False`, `config` 상수 그대로) hist →
`signal_engine.evaluate_macd_crossover` 의 제로크로스 규칙 + 같은 repeat suppression.

```
prev_diff <= 0 and cur_diff > 0 -> RED      prev_diff >= 0 and cur_diff < 0 -> BLUE
직전 확정방향과 같으면 HOLD
```

production 이 3분 **형성봉**을 매 tick 평가하는 것과 달리 MU 는 완성 1분봉만 있으므로
**플래그 인지 시각 = 그 1분봉 종료(F_end)**. 미래 데이터 없음.

**판정 시각 T = F_end + 2분** — MU Assist 의 T+2 와 같은 자리다.
`mu_assist.evaluate_pattern(series, dir, flag_bar_dt=F_end−3분)` 로 호출하면 `d0 = F_end` 가 되어
MU_POST2 = r(0,+2), MU_ACC2 = 1.5·r(0,+2) − r(−3,0), hold_ok = h(D),h(D+1),h(D+2) > 0 이
**사전등록 정의 그대로** 적용된다. 새 임계값 없음.

상태 매핑 (사용자 지정 3분류 ↔ production 패턴):

| 사용자 분류 | production `mu_pattern_state` |
|---|---|
| A. CONFIRM | `PATTERN_CONFIRM` |
| B. BAD | `PATTERN_DIVERGE` |
| C. WAIT | `PATTERN_STALL` |

## 3. 지시하신 규칙 B — **WAIT 가지가 역효과다**

```
MU CONFIRM        -> 진입
MU BAD            -> 차단
MU WAIT           -> HY 체결강도 방향일치 AND 직전 반대방향 HY gap <= 400 이면 진입
```

| | n | 30분 | 14:50 까지 | TP1 선 | 건/일 |
|---|---|---|---|---|---|
| CONFIRM 진입 | 103 | +0.175% | −0.113% | 30.1% | 10.3 |
| **WAIT 승인** | 28 | **−0.420%** | −0.293% | 21.4% | 2.8 |
| WAIT 차단 | 112 | −0.097% | +0.088% | 30.4% | 11.2 |
| BAD 차단 | 53 | −0.118% | −0.311% | 32.1% | 5.3 |
| **B 진입 전체** | **131** | **+0.048%** | −0.152% | 28.2% | 13.1 |

**체결강도 ∧ 반대gap≤400 조합은 STALL 중에서 더 나쁜 쪽을 골라낸다.** WAIT 가지를 붙이면
CONFIRM 단독(+0.175%)이 +0.048% 로 희석된다. 차단한 WAIT(−0.097%)가 승인한 WAIT(−0.420%)보다
낫다 — 이 조건은 판별력이 **거꾸로**다.

> 주의: `SELECTIVE_WAIT` 라는 이름의 계산은 저장소에 없다(전수 검색). "반대방향 gap ≤ 400" 은
> 판정 시각의 방향부호 3분 MACD gap 이 음수일 때 그 절대값으로 구현했다.

"복잡한 HY 구조를 걷어내면 더 낫다" 는 가설은 이 표본에서 **반증됐다** — 걷어내면 손실이 늘어난다.

## 9. MU 선행성은 실재한다 (다만 그것만으로는 못 번다)

- 1시간 안에 **같은 방향 HY 플래그가 뒤따른 MU 플래그 203/299건 (68%)**
- 선행 분수: 중앙값 **22분** · 평균 23.8분
  (0분 8건 / 1~5분 32건 / 6~15분 43건 / 16분+ 120건)
- HY 가 따라온 플래그 r30 **+0.012%** vs 안 따라온 것 −0.136%

S2 승자 다수가 **HY gap 이 아직 반대 방향일 때** 들어간다(10/19 10:04 opp=1964 → +3.39%,
10/23 11:10 opp=2010 → +2.07%). 선행성은 실제 값이지만, 그 값을 **현행 슬롯 구조 안에서
현금화하지 못한다** — 이른 신호가 슬롯을 먹고 더 좋은 후속을 막기 때문이다.

## 10. 판정

> **복잡한 HY 구조보다 단순 MU 구조가 더 낫지는 않다.**

1. **지시하신 원안 규칙 B 는 그대로는 쓸 수 없다.** WAIT 가지(체결강도 ∧ 반대gap≤400)가
   판별력이 거꾸로다 — 차단한 WAIT 가 승인한 WAIT 보다 낫다. 그 가지를 빼고 CONFIRM 만
   써도 하루 10건이라 슬롯 구조와 맞지 않는다.
2. **MU 플래그를 쓸 만하게 만드는 선별은 이미 production 안에 있다** — XS 의 STRONG 정의
   (CONFIRM ∧ 체결강도 ∧ gap EXPAND). 새 임계값은 필요 없었다. 플래그당 기대값은
   +0.601%/30분으로 분명히 양수다.
3. **그런데도 전체 성과는 진다.** 원인은 신호 품질이 아니라 **타이밍과 슬롯 경쟁**이다 —
   MU STRONG 은 09:56 이전에 서지 않아 오전 큰 승자를 못 보고, 오전 중반 신호가 2슬롯을
   먹어 오후 큰 승자를 막는다.
4. **HY 게이트는 지우면 안 된다.** TEG/VWAP veto 를 유지하면 MDD 가 74% 줄어든다.

### 쓸 수 있는 방향 (다음 연구 후보, 이번엔 측정 안 함)

- MU STRONG 을 **독립 진입원이 아니라 슬롯 추가 후보**로 — 현행 진입을 그대로 두고
  슬롯이 남았을 때만 S2 를 태운다. 큰 승자를 안 밀어내면서 10/22·10/23 의 신규 승자를 집는다.
- 다만 **표본 10일이라 채택 판단 불가**다. MU 수집이 30일 이상 쌓인 뒤 다시 볼 것.
